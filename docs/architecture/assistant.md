# AI Dashboard Assistant

Detailed reference for the dashboard assistant (`internal/core/assistant` + `internal/app/ai` + `cmd/ai`). Linked from the root [`CLAUDE.md`](../../CLAUDE.md) — read this when working on the assistant's turn pipeline, tools, repair loop, or deployment. Ported from the retired TypeScript service (`es/pug-sh/ai`); design: [`docs/superpowers/specs/2026-08-12-ai-assistant-go-port-design.md`](../superpowers/specs/2026-08-12-ai-assistant-go-port-design.md).

The service implements `ai.dashboards.v1.DashboardAssistantService.Turn` (server-streaming): one user message against a client-owned dashboard draft in; streamed assistant prose plus validated `TileOp`s out, in the deterministic chunk order **text → ops → done** (tools cannot yield mid-stream; the op sink drains only after the model stream completes). Ops, never whole-draft rewrites: `DashboardsService.Upsert` deletes tiles absent from its request, so an operation contract is what makes silence unable to delete. The client owns the draft and its reducer; the webapp commits via `Upsert`. Markdown tiles are not authored — insight tiles only.

**Topology.** `cmd/ai` (default port `PUG_AI_PORT`=8001) has exactly two external dependencies: Redis (history + traces, via `REDIS_URL`) and the main pug API (`PUG_API_BASE_URL`) reached through an `insightsv1connect` client with per-call forwarded `Authorization` + `x-project-id` headers. No Postgres, no ClickHouse, no NATS. Misconfiguration fails at boot (crash-loop loudly); there is no idle mode — an ai Deployment exists only to serve. Exposed three ways: `pug ai`, a `MODEL_AGENT`-gated component of `pug dev` (`ai.DevStatus`), and the `pug-ai` per-role image (release matrix row `{name: ai, cmd: ai, target: app}`).

**Auth.** `WithAssistantAuth` is a local JWT **spend gate**, not the security boundary: the DB-free core of the server's `WithJWTAuth` (bearer + HS256 + `coreauth.Issuer`/`Audience` + required expiry, needs `PUG_JWT_SECRET_KEY`) plus a required `x-project-id`. It rejects junk before model spend — a turn with no tool calls would otherwise never be rejected — while a revoked-but-unexpired token still passes locally and is enforced by the insights callback, which re-runs full auth (including org membership for the named project) on every tool call. The service holds no credentials of its own; a viewer cannot escalate through the assistant. The ai mux is deliberately **outside** the server's authz registry/contract tests (those cover only the server's mux), mirroring how `/mcp` owns its own boundary. The caller's JWT and tile content are never logged and never stored in traces.

**Turn pipeline** (`Service.Turn`): load history (Redis outage → `CodeUnavailable` "conversation storage unavailable (load)" — **fail closed**; silently serving empty history reads as "the model forgot everything") → build per-turn tools → `aisdk.StreamText` with messages `[draft summary, …history, user message]`, `WithStopWhen(StepCountIs(12))` (the SDK default is ONE step), text deltas emitted as they arrive → drain the op sink → append user+assistant messages, save history (fail closed, "(save)") → best-effort debug trace (log + `telemetry.RecordError`, never fails the turn) → `done{failed}`.

**Tools.** Three insight reads (`get_insights_filter_schema`, `get_insights_property_values`, `query_insights`) over the shared Connect API, and three ops (`add_tile`, `update_tile`, `remove_tile`). Tool failures are returned to the model as `ERROR: …` strings, never as Go errors — the grafana SDK wouldn't abort the turn on an Execute error (unlike the TS SDK this ports), but string returns keep the model-visible format identical to the TS service and out of the SDK's error-result wrapping.

**Repair loop.** A submitted tile is decoded with `protojson` (real proto3 JSON — flat oneof member keys; unknown fields are parse failures) and validated with protovalidate-go against the same rules `Upsert` enforces. Violations are handed back to the model as the tool reply — that IS the repair loop. Budget: 3 attempts **per intent**, shared across parse and validation failures; past budget the tile is emitted **flagged** (`TileOp.violations` non-empty — the client must block save; `Upsert` re-enforces server-side) — never silently dropped. A `givenUp` latch stops repeat emissions after the budget. A validator runtime error (`validator.error`) fails the tile outright into `TurnDone.failed`: fail-closed, an unvalidated tile is never emitted as if checked. Because flagged tiles are deliberately invalid protos, the ai server's validate interceptor must NEVER get `WithValidateResponses()`. `exampleTileJSON` (the worked example in the tool descriptions) is rendered from the generated types via protojson — a proto rename breaks the build, not a prompt string — and a self-check test asserts it validates.

**Placement** (`placement.go`): append-below — new tiles at x=0 under the lowest existing tile; the model's proposed w/h are honored and clamped (w≤72, h≤60), its x/y ignored, so overlap is unrepresentable. Always returns a complete position (the `grid_position.complete` CEL rule rejects partial ones).

**Redis shapes** (byte-compatible with the TS service; in-flight conversations survive cutover): `conversation:<id>:messages` = `[{"role":<enum int>,"content":"…"}]`, `debug:<id>` = RPUSH'd `TurnTrace` JSON (`projectId`, `message`, `reply`, `toolCalls[{toolName,input,output}]`, `ops`, `failed[{intent,violations}]`, `model`, `durationMs` — no JWT field by design). Both carry a 7-day TTL refreshed on write.

**Model routing** (`llm.go`): `MODEL_AGENT=provider:model?opts`, parsed at boot. Providers: `anthropic` (`ANTHROPIC_API_KEY`), `openai` (`OPENAI_API_KEY`, Responses API), `openai-compatible` (`base_url` required; optional `api_key_env` names the key env — omit for local servers like Ollama). Sampling opts (`temperature`/`top_p`/`top_k`) become per-call options, **stripped for anthropic** (its current models 400 on them). The grafana ai-sdk (`v0.1.0-alpha.1`; provider submodules pinned by pseudo-version — they are untagged) is confined to `loop.go` + `llm.go`; everything else sees only `provider.LanguageModel` and the `CallOptions` named type, and tests drive the loop with `assistanttest.ScriptedModel`.

**Env contract:** `PUG_AI_PORT` (8001), `PUG_API_BASE_URL` (required), `PUG_JWT_SECRET_KEY` (required), `MODEL_AGENT` (required) + provider key env, `REDIS_URL` (required), `PUG_CORS_ORIGINS` (`*`) — same CORS var as the server; `pogrpc.WithCORS` already allows `Authorization` + `X-Project-Id`.

Tests: unit suite is `-short`-safe; history/trace/service/handler tests ride `testutil.SetupRedis` (package wires `testutil.Main`, no `t.Parallel`). The handler tests are the wire-contract round-trip: a real generated streaming client against the same `buildMux` production uses.
