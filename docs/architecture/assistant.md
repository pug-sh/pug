# AI Dashboard Assistant

Detailed reference for the dashboard assistant (`internal/core/assistant` + `internal/app/ai` + `cmd/ai`). Linked from the root [`CLAUDE.md`](../../CLAUDE.md) — read this when working on the assistant's turn pipeline, tools, repair loop, or deployment. Ported from the retired TypeScript service (`es/pug-sh/ai`).

The service implements `ai.dashboards.v1.DashboardAssistantService.Turn` (server-streaming): one user message against a client-owned dashboard draft in; streamed assistant prose plus validated `TileOp`s out, in the deterministic chunk order **text → ops → done** (tools cannot yield mid-stream; the op sink drains only after the model stream completes). Ops, never whole-draft rewrites: `DashboardsService.Upsert` deletes tiles absent from its request, so an operation contract is what makes silence unable to delete. The client owns the draft and its reducer; the webapp commits via `Upsert`. Markdown tiles are not authored — insight tiles only.

**Topology.** `cmd/ai` (default port `PUG_AI_PORT`=8001) has exactly two external dependencies: Redis (history + traces, via `REDIS_URL`) and the main pug API (`PUG_API_BASE_URL`) reached through an `insightsv1connect` client with per-call forwarded `Authorization` + `x-project-id` headers. No Postgres, no ClickHouse, no NATS. Misconfiguration fails at boot (crash-loop loudly); there is no idle mode — an ai Deployment exists only to serve. Exposed three ways: `pug ai`, a `MODEL_AGENT`-gated component of `pug dev` (`ai.DevStatus`), and the `pug-ai` per-role image (release matrix row `{name: ai, cmd: ai, target: app}`).

**Auth.** `WithAssistantAuth` is a local JWT **spend gate**, not the security boundary: the DB-free core of the server's `WithJWTAuth` (bearer + HS256 + `coreauth.Issuer`/`Audience` + required expiry, needs `PUG_JWT_SECRET_KEY`) plus a required `x-project-id`. It rejects junk before model spend — a turn with no tool calls would otherwise never be rejected — while a revoked-but-unexpired token still passes locally and is enforced by the insights callback, which re-runs full auth (including org membership for the named project) on every tool call. The service holds no credentials of its own; a viewer cannot escalate through the assistant. The ai mux is deliberately **outside** the server's authz registry/contract tests (those cover only the server's mux), mirroring how `/mcp` owns its own boundary. The caller's JWT and tile content are never logged and never stored in traces.

**Turn pipeline** (`Service.Turn`): apply the turn deadline (`turnTimeout`, 5m — a stream has none of its own, and `maxSteps` rounds of 60s insight calls compose to far longer than any real turn; `DeadlineExceeded`/`Canceled` map to their own Connect codes so an abandoned stream is not logged as a server fault) → reject an incomplete caller scope (`ErrIncompleteScope`) → load history (Redis outage → `CodeUnavailable` "conversation storage unavailable (load)" — **fail closed**; silently serving empty history reads as "the model forgot everything") → build per-turn tools → `aisdk.StreamText` with messages `[draft summary, …history, user message]`, `WithStopWhen(StepCountIs(12))` (the SDK default is ONE step), text deltas emitted as they arrive → partition the op sink → append user+assistant messages, save history (fail closed, "(save)") → best-effort debug trace (log + `telemetry.RecordError`, never fails the turn) → **then** emit the ops. Ops go last because one the client has applied is a durable draft change, so a save failure has to precede it; the trace is written before them so the one turn that diverges — history committed, emission failed — is the one that leaves a record.

**Tools.** Three insight reads (`get_insights_filter_schema`, `get_insights_property_values`, `query_insights`) over the shared Connect API, and three ops (`add_tile`, `update_tile`, `remove_tile`). Tool failures are returned to the model as `ERROR: …` strings, never as Go errors — the grafana SDK wouldn't abort the turn on an Execute error (unlike the TS SDK this ports), but string returns keep the model-visible format identical to the TS service and out of the SDK's error-result wrapping. That string is the *repair* channel only: `safely` also logs, splitting on the Connect code (`modelRepairable`) so the model's own mistakes stay at warn while an upstream failure is an error + `telemetry.RecordError` — otherwise an insights outage would be invisible to operators. `remove_tile` is the one destructive op and the only one that checks its id against the draft; a tile added earlier in the same turn has no id until `Upsert` assigns one, so the draft is the whole universe of removable ids.

**Repair loop.** A submitted tile is decoded with `protojson` (real proto3 JSON — flat oneof member keys; unknown fields are parse failures) and validated with protovalidate-go against the same rules `Upsert` enforces. Violations are handed back to the model as the tool reply — that IS the repair loop. Budget: 3 attempts **per intent**, shared across parse and validation failures; past budget the tile is emitted **flagged** (`TileOp.violations` non-empty — the client must block save; `Upsert` re-enforces server-side) — never silently dropped. A `givenUp` latch stops repeat emissions after the budget. `intent` carries `minLength: 1` in both tool schemas (the SDK validates a tool's `InputSchema` before `Execute`), so unlabelled tiles cannot collapse into one shared budget. A validator runtime error (`validator.error`) fails the tile outright into `TurnDone.failed`: fail-closed, an unvalidated tile is never emitted as if checked. Because flagged tiles are deliberately invalid protos, the ai server's validate interceptor must NEVER get `WithValidateResponses()`. `exampleTileJSON` (the worked example in the tool descriptions) is rendered from the generated types via protojson — a proto rename breaks the build, not a prompt string — and a self-check test asserts it validates.

**Placement** (`placement.go`): append-below — new tiles at x=0 under the lowest existing tile; the model's proposed w/h are honored and clamped (w≤72, h≤60), its x/y ignored, so overlap is unrepresentable. Always returns a complete position (the `grid_position.complete` CEL rule rejects partial ones). The cursor is turn-scoped: the client applies ops only after the turn, so tiles added earlier this turn are not in the draft and re-reading it would stack them all on one row. It advances only when a tile is emitted, so a repair retry does not burn a row. **`update_tile` keeps the edited tile's existing position** — an update changes what a tile shows, not where it sits — and falls back to append-below only for an id the draft does not have.

**Concurrency.** The SDK executes every tool call in a step on its own goroutine and makes goroutine safety the caller's problem (`openspec/specs/concurrent-tool-execution/spec.md` in the pinned `v0.1.0-alpha.1`), with no way to serialize. `buildOpTools` therefore guards all four pieces of turn state — `attempts`, `givenUp`, the placement cursor, and the op sink — under one mutex. Unguarded, two `add_tile` calls in one step race the maps (a fatal runtime error no `recover` catches, so `RecoverHandlerPanic` would not contain it) and lose ops to concurrent appends.

**Redis shapes.** Keys are scoped `<project_id>:<customer_id>:<conversation_id>` (`keyScope`): `conversation:<scope>:messages` = `[{"role":<enum int>,"content":"…"}]`, `debug:<scope>` = RPUSH'd `TurnTrace` JSON (`projectId`, `message`, `reply`, `toolCalls[{toolName,input,output}]`, `ops`, `failed[{intent,violations}]`, `model`, `durationMs` — no JWT field by design). Both carry a 7-day TTL refreshed on write. `conversation_id` is client-minted, so the scope is the only thing keeping one caller's conversation out of another's reach; `Turn` fails closed on an incomplete scope (`ErrIncompleteScope` → `Unauthenticated`). The JWT-derived `customer_id` sits in the middle, so a forged project or conversation id cannot land on another caller's key — and both outer segments are charset-bounded anyway (`^[A-Za-z0-9_-]+$`; `conversation_id` ≤128 in the proto, `x-project-id` ≤64 in `WithAssistantAuth`). The **values** stay byte-compatible with the retired TS service; the **keys** deliberately are not, so its in-flight conversations do not carry over — 7-day working data, nothing to migrate.

**Model routing** (`llm.go`): `MODEL_AGENT=provider:model?opts`, parsed at boot. Providers: `anthropic` (`ANTHROPIC_API_KEY`), `openai` (`OPENAI_API_KEY`, Responses API), `openai-compatible` (`base_url` required; optional `api_key_env` names the key env — omit for local servers like Ollama). Sampling opts (`temperature`/`top_p`/`top_k`) become per-call options, **stripped for anthropic** (its current models 400 on them). The grafana ai-sdk (`v0.1.0-alpha.1`; provider submodules pinned by pseudo-version — they are untagged) is confined to `loop.go` + `llm.go`; everything else sees only `provider.LanguageModel` and the `CallOptions` named type, and tests drive the loop with `assistanttest.ScriptedModel`.

**Env contract:** `PUG_AI_PORT` (8001), `PUG_API_BASE_URL` (required), `PUG_JWT_SECRET_KEY` (required), `MODEL_AGENT` (required) + provider key env, `REDIS_URL` (required), `PUG_CORS_ORIGINS` (`*`) — same CORS var as the server; `pogrpc.WithCORS` already allows `Authorization` + `X-Project-Id`.

Tests: unit suite is `-short`-safe; history/trace/service/handler tests ride `testutil.SetupRedis` (package wires `testutil.Main`, no `t.Parallel`). The handler tests are the wire-contract round-trip: a real generated streaming client against the same `buildMux` production uses.
